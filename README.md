# Tower of Gods

2D 횡스크롤 보스러시 액션. **LinUCB 기반 동적 난이도 조절(DDA)이 보스 패턴 단위로 작동한다.**

> 기획 단계의 이름은 *역전의 탑(Tower of Reversal)* 이었다. 2026-10-23 에 **Tower of Gods** 로 바꿨다.
> 보스 다섯이 *신의 명령을 받은 세 형제 · 그 아버지(신) · 먼저 반역한 자* 이므로 바뀐 이름이 더 맞는다.
> 다만 궁극기 계승 시스템은 원래 '역전' 이라는 말에서 나온 것이라, 그 컨셉 문구는 손봐야 할 수 있다.

> 팀 프로젝트(`kimdal0803/Team_RedBull_Project`)와 **코드를 공유하지 않는** 1인 재구현이다.
> 기획 자료만 가져오고 구조는 처음부터 다시 잡았다. 이유는 `docs/ARCHITECTURE.md` §0.

## 지금 상태

**2단계 — 전투** ✅

허수아비를 때리고, 패링하고, 패링이 **안 통하는** 공격을 구분할 수 있다.

```
Tower of Gods ▸ 2단계 전투 테스트 씬 만들기   ← 메뉴 한 번이면 씬이 만들어진다
```

그 뒤 **Play** → **Game 창 클릭**.

| 키 | 하는 일 |
|---|---|
| `A` `D` | 이동 |
| `Space` | 점프 (코요테 0.1s · 버퍼 0.15s · 가변 높이) |
| `Shift` | 대시 (스택 2 · 앞 0.15s 무적, **끝 0.05s는 맞는다**) |
| `Z` | 검 콤보 1·2타 (유예 0.4s · 넉백 없음) |
| `F` | 패링 (입력 지연 0.05 → 판정 0.15 → 실패 후딜 0.35) |
| `Q` `W` `E` | 돌진 베기 6s · 회전 베기 10s · 처형 베기 15s |
| `F1` | 디버그 창 |
| `F2` | 층 진입 상태로 초기화 (죽어도 듣는다) |

오른쪽 허수아비가 **네 종류**를 돌아가며 예고한다.
이게 2단계에서 반드시 눈으로 확인해야 할 것이다:

| 색 | 패링 | 대시 | 확인할 것 |
|---|---|---|---|
| 노랑 | O | O | 가장 흔한 패턴 |
| 빨강 | **X** | O | `F`를 눌러도 **맞아야** 정상 |
| 보라 | **X** | **X** | 범위를 벗어나는 수밖에 없다 |
| 주황 | O | **X** | **패링만 통한다** — 설계상 가장 중요한 칸 |

마지막 칸이 없으면 모든 상황에서 대시가 패링의 상위 호환이 되어
"보스 패턴의 35~40%만 패링 가능" 이라는 설계 전체가 무의미해진다.
팀 프로젝트가 정확히 그 상태였다 — `HitData.parryable` 은 있었지만
플레이어 쪽에 그걸 받을 자리가 없었다.

> **1단계** 씬도 그대로 있다: `Tower of Gods ▸ 1단계 테스트 씬 만들기`

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 뼈대 · 어셈블리 · 입력 인터페이스 | ✅ |
| 1 | 플레이어 기동 (이동·점프·대시·코요테·버퍼) | ✅ |
| 2 | 전투 (콤보·Q/W/E·패링·피격·히트스톱) | ✅ |
| 3 | 보스 프레임워크 (PatternExecutor 6종) | ⬜ |
| 4 | 아라쿠스 | ⬜ |
| 5 | 텔레메트리 + Supabase | ⬜ |
| 6 | **DDA** — 여기까지면 논문 실험이 가능하다 | ⬜ |
| 7 | 로비 · 성장 · 궁극기 계승 | ⬜ |
| 8~11 | 아디쿠스 · 파네스 · 에텔로스 · 카로스 | ⬜ |

## 구조

```
Assets/_Project/
├─ Core/        이벤트 · 인터페이스 · 공용 타입   (아무것도 참조하지 않음)
├─ Data/        ScriptableObject 정의
├─ Player/      플레이어 상태 기계 · 입력 구현
├─ Boss/        보스 FSM · 패턴 실행기
├─ Telemetry/   전투 기록
├─ Backend/     Supabase 연동
├─ DDA/
│  ├─ Model/    LinUCB 학습 코어 — **UnityEngine을 참조하지 않는 순수 C#**
│  └─ Runtime/  유니티 쪽 매니저
├─ UI/
├─ Game/        부트스트랩 · 조립 (유일하게 전부를 참조한다)
└─ Tests/
```

### 의존 방향

```
Core ← Data ← {Player, Boss, Telemetry, UI}
                    ↑
            Backend, DDA ← Telemetry
                    ↑
                  Game  (조립만)
```

**Assembly Definition으로 컴파일 단계에서 강제한다.** 규칙을 어기면 빌드가 깨진다.

## 지키는 규칙

1. 한 파일 **300줄**을 넘기지 않는다 — 넘으면 "쪼갤까?"를 생각하는 신호등
2. 매직 넘버 금지 — 수치는 ScriptableObject
3. **`UnityEngine.Input`을 쓰는 곳은 `KeyboardInput.cs` 하나뿐이다**
   나머지는 전부 `IPlayerInput`을 본다 → 에이전트·리플레이로 갈아끼울 수 있다
4. `RT.DDA`는 `RT.Boss`·`RT.Player`를 참조하지 않는다 → **DDA를 빼도 게임이 돈다 = 대조군 빌드가 공짜**
5. `RT.Backend`가 꺼져도 게임이 끝까지 돌아간다 → 로컬 CSV로 폴백
6. DDA 학습 코어는 유니티 없이 테스트된다

## 패키지에 관한 메모

`Packages/manifest.json` 에 **버전을 직접 적은 패키지는 최소한으로 둔다.**

2D Animation 패키지를 `10.1.4` 로 박았다가 컴파일이 통째로 깨진 적이 있다.
그 버전 코드가 `Object.GetInstanceID()` 를 쓰는데 Unity 6000.6 에서 폐기돼
`GetEntityId()` 로 바뀌었기 때문이다. 패키지 안에서 에러가 18개 났다.

→ **나중에 패키지가 필요하면 `manifest.json` 을 손으로 고치지 말고,
Window ▸ Package Manager 에서 설치한다.** 유니티가 호환되는 버전을 알아서 고른다.

2D 리깅(2D Animation)은 8단계 이후 아트를 붙일 때 그렇게 추가한다.
